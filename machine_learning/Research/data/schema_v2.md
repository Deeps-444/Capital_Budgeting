# Raw Dataset Schema — Capital Budgeting DSS

## Purpose

This dataset represents **project-level historical data** containing project characteristics, financial/project drivers, yearly economic conditions, yearly financial performance, and actual project cash flow.

It is designed to support research on **predicting future cash flows of investment projects for capital-budgeting decisions**.

The raw dataset should contain meaningful, realistically observable project information. Derived features and decision metrics will be calculated later during feature engineering and model experiments.

---

## Dataset Structure

**Format:** Long format

**One row = one project in one year.**

A project appears in multiple rows, one for each year of its project life.

```text
P001 | Year 1
P001 | Year 2
P001 | Year 3
P001 | Year 4
P001 | Year 5
P002 | Year 1
P002 | Year 2
...
```

---

## Schema

| Column | Type | Level | Description |
|---|---|---|---|
| `project_id` | String | Project | Unique identifier for each project |
| `project_type` | Categorical | Project | Type/sector of the investment project |
| `project_scale` | Categorical | Project | Overall project size: Small, Medium, or Large |
| `project_duration_years` | Integer | Project | Expected economic/operating life of the project |
| `complexity_index` | Numeric | Project | Measure of project complexity |
| `initial_investment` | Numeric | Project | Initial capital required at Year 0 |
| `tax_rate` | Numeric | Project | Applicable tax rate/assumption |
| `risk_index` | Numeric | Project | Overall project/sector risk level |
| `year` | Integer | Year | Project year, e.g. 1, 2, 3, 4, 5 |
| `inflation_rate` | Numeric | Year | Inflation rate applicable during that project year |
| `market_growth_rate` | Numeric | Year | Growth or decline in the relevant market |
| `revenue` | Numeric | Year | Revenue generated by the project during that year |
| `operating_cost` | Numeric | Year | Operating expenses incurred during that year |
| `capex` | Numeric | Year | Capital expenditure incurred during that year |
| `working_capital` | Numeric | Year | Working capital tied up in the project during that year |
| `cash_flow` | Numeric | Year | Actual project cash flow for that year; primary prediction target |

## Important Design Rules

### 1. One master raw dataset

There should be **one raw dataset**, rather than separate historical, training, testing, and proposed-project datasets.

Training/test splits will be created later during experiments.

### 2. Historical information comes from the same dataset

Historical project information should not be stored as a separate artificial dataset.

Later, historical information can be transformed into derived features such as:

```text
average_cash_flow
average_ROI
cost_overrun_rate
average_project_duration
historical_failure_rate
cash_flow_volatility
```

These should **not** be precomputed in the raw dataset.

### 3. Downstream decision metrics are excluded

The following should be calculated after cash-flow prediction:

```text
NPV
IRR
Payback Period
Profitability Index
Investment Decision
```

They are outputs of the capital-budgeting/DSS stage, not raw project observations.

### 4. Avoid unnecessary variables

Every raw variable should have a clear business/economic reason for existing.

The objective is not to maximize the number of columns, but to create a realistic dataset that supports meaningful comparisons between modelling approaches.

---

## Research Use

The same raw dataset can later support:

- **Statistical/regression models** — project drivers → future cash flow
- **Tree-based ML** — nonlinear relationships between project drivers and cash flow
- **CBR/similar-project models** — historical projects → similar-project information
- **Neural networks** — nonlinear project-driver relationships
- **Time-series/sequence models** — yearly project observations where sequential modelling is appropriate
- **Probabilistic models** — uncertainty and risk around future cash flows
